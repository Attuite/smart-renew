# 智更 Smart Renew 网站目录与层级重构实施方案

> 建立日期：2026-07-28  
> 适用分支：`姚博迪修改`  
> 实施原则：先调整信息架构，再拆分代码；不改变现有业务数据，不虚构页面或统计数据。

## 1. 改造目标

当前网站的核心功能已经基本完整，本次调整不重新设计业务流程，主要解决以下问题：

1. 顶部导航同时混合“操作、业务对象、分析维度和成果”，入口过多。
2. 住区分析、社区／街区分析和报告都必须先选择项目，但页面仍作为独立一级入口。
3. 项目详情与独立分析页面存在功能重复，用户容易失去当前项目上下文。
4. 指标标准、项目指标结果、问题台账和报告引用之间的层级不够清晰。
5. 页面、样式和业务逻辑集中在大型 `index.html` 中，后续修改风险持续增加。

重构后的核心原则：

```text
平台负责进入工作
项目负责承载业务
任务负责产生数据
问题和指标负责统一归档
报告负责读取正式数据
```

## 2. 目标一级目录

网站业务一级导航调整为以下 5 项，顶部另保留“首页”作为品牌门户入口：

```text
智更 Smart Renew
├─ 工作台
├─ 项目管理
├─ 现场采集
├─ 成果中心
└─ 系统设置
```

### 2.1 工作台

工作台只展示真实数据和需要继续处理的事项：

- 当前项目；
- 最近访问项目；
- 待补录的小区、楼栋和户数；
- 待复核的 AI 分析结果；
- 最近上传的现场照片；
- 待生成或待更新的项目报告。

没有真实数据时显示明确空状态，不生成示例数字。

### 2.2 项目管理

项目管理包含：

- 项目列表；
- 新建项目；
- 项目搜索和筛选；
- 打开项目工作台；
- 设置当前项目；
- 项目基础状态。

“新建项目”不再作为一级导航，改为项目管理中的主要操作按钮。

### 2.3 现场采集

现场采集包含：

- 微信小程序入口和使用说明；
- 现场采集任务；
- 照片上传状态；
- 失败任务重试；
- 照片档案；
- 按项目、小区、楼栋和问题编码筛选照片。

### 2.4 成果中心

成果中心用于跨项目查看正式成果：

- 项目数据看板；
- 问题统计；
- 指标统计；
- 报告档案；
- 报告版本；
- 正式数据导出。

### 2.5 系统设置

系统设置包含：

- AI 服务接口和模型配置；
- 用户密钥管理；
- 指标标准库维护；
- 问题编码维护；
- 外部接口配置；
- 系统运行状态。

普通业务页面不再直接显示模型密钥或技术接口配置。

## 3. 项目工作台层级

打开具体项目后，所有工作都保持在该项目上下文中。

```text
项目工作台
├─ 项目概览
├─ 档案与范围
├─ 住宅台账
├─ 现场照片
├─ 体检分析
│  ├─ 住区维度
│  └─ 社区／街区维度
├─ 问题台账
├─ 指标库
└─ 报告成果
```

项目页面顶部固定展示：

- 项目名称；
- 项目位置；
- 当前项目状态；
- 范围面积；
- 小区、楼栋和户数；
- 待处理事项；
- 返回项目列表入口。

切换项目内部栏目时，不丢失项目编号和当前项目状态。

## 4. 现有页面迁移对照

| 现有入口 | 调整后位置 | 处理方式 |
|---|---|---|
| 首页 | 工作台 | 保留品牌首页内容，业务入口改为工作台 |
| 新建项目 | 项目管理／新建项目 | 从一级导航移除 |
| 项目汇总 | 项目管理 | 更名并作为项目统一入口 |
| 住区维度 | 项目工作台／体检分析／住区维度 | 保留功能，迁移入口 |
| 照片档案 | 项目工作台／现场照片 | 从住区分析页中独立出来 |
| 社区／街区维度 | 项目工作台／体检分析／社区／街区维度 | 保留功能，迁移入口 |
| 体检报告 | 项目工作台／报告成果 | 项目内生成，成果中心归档 |
| 数据看板 | 成果中心 | 作为跨项目汇总入口 |
| AI 配置 | 系统设置 | 从业务页面移除 |
| 历史分析 | 项目工作台／体检分析／分析记录 | 按项目归档 |

## 5. 指标库与问题编码层级

指标库底层只保留一套标准数据，页面按用途提供不同视角。

```text
指标标准
└─ IND-HOUSE-001 结构安全指标
   └─ PRB-01-01 混凝土结构构件裂缝
      ├─ 现场照片
      ├─ AI 候选问题
      ├─ 人工复核记录
      ├─ 正式问题台账
      ├─ 小区和楼栋
      └─ 报告引用
```

规则：

1. 每个细分小类使用唯一 `problemCode`，例如 `PRB-01-01`。
2. 页面、小程序和外部接口只提交 `problemCode`。
3. 系统通过编码自动取得名称、所属大类和上级指标。
4. 已投入使用的编码不得改号、删除或重新分配。
5. 名称调整时只修改标准库，不批量修改历史记录。
6. 未收录的编码拒绝保存。
7. 项目统计只统计经过人工复核的正式问题。

指标库页面分成两个视角，但使用同一个数据源：

- 标准指标：展示指标和问题编码定义；
- 项目结果：展示当前项目各编码对应的问题数量、位置和证据。

## 6. 目标业务流程

```text
新建项目
→ 框选项目范围
→ 识别并核实小区
→ 补录楼栋和户数
→ 现场拍照与分类
→ 照片归档
→ AI 识别
→ 人工复核
→ 按 PRB 编码形成正式问题
→ 汇总项目指标
→ 生成报告和版本快照
```

流程要求：

- 每个业务动作必须属于具体项目；
- 照片必须属于具体小区，可选具体楼栋；
- AI 输出首先进入候选问题，不直接进入统计；
- 人工确认后才进入正式问题台账；
- 报告只读取正式数据库记录；
- 跨项目统计只在成果中心进行。

## 8. 提交拆分建议

建议每个阶段使用独立提交：

```text
调整平台一级导航与旧路由兼容
建立统一项目工作台
迁移项目台账与现场照片
迁移住区和社区街区分析
整理问题台账与指标库层级

迁移系统设置与AI配置
拆分前端路由和基础服务

```

禁止把导航调整、业务重写、数据库迁移和线上部署放在同一次提交中。

## 9. 风险与回滚规则

1. 每个阶段必须能够单独回滚。
2. 不删除旧路由，先保留跳转兼容。
3. 不修改项目、照片和问题的稳定编号。
4. 不自动迁移或删除线上真实数据。
5. 不在页面重构时同步更换后端存储方案。
6. 出现数据归属错误时立即停止后续阶段。
7. 上线失败时恢复上一个已验证的 `main` 提交。

## 10. 最终验收目标

完成全部阶段后，网站应达到：

- 一级导航清晰且不超过 5 项；
- 用户始终知道当前项目；
- 项目业务按真实工作顺序排列；
- 同一功能只保留一个主要入口；
- 所有照片、问题、指标和报告可以通过稳定编码追溯；
- 工作台和看板只展示真实数据；
- 页面代码可以按模块单独维护；
- 本地、Git `main` 和线上版本可以明确对应。
